# SundayRUN — Воскресный парковый пробег

Бесплатное веб-приложение клуба «Воскресный парковый пробег» (Таганрог, КЛБ «Легенда»). Организатор загружает xlsx-экспорт приложения-секундомера (можно сразу несколько) → приложение определяет пол участников, считает места и авто-примечания → одним атомарным коммитом публикует результаты в базу `data/sundayrun.db` этого же репозитория (`sundayrun`). PDF-протокол по официальному образцу генерируется на лету в браузере (в мастере публикации и по кнопке «PDF» в архиве) — в репозитории он не хранится. Сайт — это архив всех забегов с 2019 года плюс статистика: рекорды, рейтинг, итоги года, очные встречи, бейджи.

## Роли

- **Посетитель** — публичные страницы без токена и без регистрации: главная `/` (лендинг со свежими забегами и общей статистикой), `/races` (все забеги), `/races/:slug` (онлайн-протокол), `/records` (зачёты, рейтинг, номинации, «Гонка за сезон»), `/year/:year` (итоги года), `/athletes/:key` (страница участника), `/vs/:left/:right` (очные встречи), `/guide` («Фишки» — как считается каждая метрика). Данные читаются анонимно из `sundayrun.db` HTTP-range-запросами; публичные страницы вдобавок пререндерены в статику, поэтому открываются мгновенно.
- **Организатор** — по неприметной ссылке «для организатора» открывает `/admin` и один раз вставляет GitHub-токен. После этого доступен мастер `/upload → /preview → /result`: загрузка одного или нескольких xlsx, правка пола/примечаний и реквизитов события, предпросмотр PDF и «Опубликовать в архив» — вся партия уходит одним атомарным коммитом (`source.xlsx` каждого забега + пересобранная `sundayrun.db`), за ним отдельный коммит-указатель `version.json`. Статистика участников (участия, финиши, рекорды за всё время и по годам, агрегаты забега, погода) пересчитывается автоматически. Ошибочно загруженный забег удаляется на `/admin` таким же атомарным коммитом — БД перезаписывается без его вклада.

## Стек

Angular 22 (standalone, zoneless, signals) · Bun · Vitest (покрытие 100%) · SQLite в браузере (`sqlite-wasm-http` + range-запросы, drizzle-orm для запросов) · CDK virtual scroll (таблицы) · fflate (парсинг xlsx) · pdfmake + PT Serif (PDF с кириллицей) · Angular SSR (пререндер публичных страниц) · GitHub Pages + GitHub API (хостинг и хранилище, всё бесплатно) · i18n: source locale `ru` (en-локаль отключена, разметка сохранена)

## Команды

```bash
bun install                  # зависимости
bun start                    # dev-сервер, http://localhost:4200 (перед запуском собирает БД и pdf-ассеты)
bun run test                 # юнит-тесты (vitest)
bun run test:coverage        # юнит-тесты + покрытие (порог 100%)
bun run check:code-quality   # prettier + eslint + stylelint
bun run build                # прод-сборка + пререндер публичных страниц
bun run preview              # локальный статик-сервер поверх dist/ (проверить сборку как на Pages)
bun run madge                # проверка циклических зависимостей
bun run generate-i18n        # извлечение i18n-сообщений → src/locale/messages.xlf
```

`bun start` и `bun run build` перед сборкой прогоняют `scripts/write-version.ts` (номер версии в бандл), `scripts/build-sqlite-assets.ts` (wasm-ассеты SQLite + патч размера файла для GitHub Pages) и `scripts/build-pdf-assets.ts` (шрифты pdfmake).

Полезные разовые скрипты в `scripts/`: `backfill-*.ts` (досчёт материализованных сводок, гендерных медиан, погоды, примечаний), `verify-notes.ts` (аудит авто-примечаний), `preview-year-review.ts` (смоук итогов года), `fix-tied-places.ts` и `add-event-*.ts` (ручные правки архива через те же функции приложения). Запускаются через `bun scripts/<файл>.ts`.

## Хранилище данных (`data/` в этом репозитории)

Код и опубликованные данные живут в одном публичном репозитории `ASDAlexey/sundayrun` (ветка `main`); все данные — под `data/`:

- `data/sundayrun.db` — **единственный источник истины**: события, участники, результаты, сводки, погода. Читается из браузера HTTP-range-запросами (см. [docs/SQLITE_DB.md](docs/SQLITE_DB.md))
- `data/version.json` — указатель на commit SHA актуальных данных; единственный файл, который читается по ветке, всё остальное — по SHA
- `data/site-meta.json` — объявление организатора (время старта + сообщение на главной)
- `data/events/<дата>/source.xlsx` — исходный экспорт секундомера, сырьё для пересборки БД (у импортированных задним числом забегов его нет)

JSON-зеркала (`index.json`, `athletes.json`, `results.json`) удалены — см. [docs/DB_ONLY_MIGRATION.md](docs/DB_ONLY_MIGRATION.md). Приложение пишет в `data/` само атомарными коммитами; вручную эти файлы не редактировать. Поскольку БД раздаётся из самой сборки (см. «Деплой»), публикация **триггерит ребилд и деплой** — новые данные доезжают до читателей за время деплоя, а сайт до этого честно показывает баннер «результаты обновляются».

## Токен организатора (fine-grained PAT)

Подробная пошаговая инструкция с ответами на частые вопросы: [docs/ADMIN_TOKEN.md](docs/ADMIN_TOKEN.md) (она же открывается по ссылке «Как создать токен» на `/admin`).

1. GitHub → Settings → Developer settings → Fine-grained personal access tokens.
2. Repository access: **Only select repositories → `sundayrun`**.
3. Permissions: **Contents → Read and write** (больше ничего).
4. Вставить токен на странице `/admin` — приложение проверит доступ и сохранит его в localStorage браузера. Токен и есть «роль админа»; сервера аутентификации нет.
5. Когда токен истечёт, публикация покажет баннер «Нет доступа к GitHub» со ссылкой на `/admin` для замены токена.

## Доимпорт старой истории

Старые забеги можно опубликовать задним числом — **строго от старых к новым**, чтобы примечания считались по истории на дату забега:

1. Загрузить xlsx (или сразу несколько — тогда порядок внутри партии приложение выстроит по датам само), на `/preview` заполнить дату и остальные реквизиты.
2. Примечания («Первое участие», «ЛР (было X)», «Лучший результат YYYY г.») подставляются автоматически из уже опубликованной истории, отсечённой до даты события; при необходимости поправить вручную.
3. Проверить предпросмотр PDF и опубликовать.

Перепубликация той же даты идемпотентна: вклад события в БД сначала снимается, потом накатывается заново — дубликатов не появляется.

## Деплой (GitHub Pages)

В настройках репозитория: **Settings → Pages → Source: GitHub Actions**. Workflow `.github/workflows/ci.yml` на каждый push в `main` (и по кнопке Run workflow):

1. `changes` — отличает изменения кода от публикации данных и выбирает вид бампа версии;
2. `quality` — prettier, eslint, stylelint, madge, тесты с покрытием 100% (скипается на публикациях данных);
3. `build` — бампит версию на кодовых пушах, собирает прод-бандл с `--base-href /<repo>/` и пререндером, кладёт рядом с `data/sundayrun.db` копию, названную по SHA данных (иммутабельный URL — кэш не может отдать её протухшей), добавляет SPA-fallback `404.html`, прогоняет smoke-проверки;
4. `deploy` — публикует на Pages.

Публикация протокола меняет только `data/**`, но деплой всё равно нужен: БД читается **с того же origin**, куда её кладёт сборка.

## Данные

Примеры входного Excel и целевого PDF — в `assets/`. Формат входа: экспорт приложения-секундомера (колонки Name, Total, Avg/lap, Avg/km, Lap 1, Lap 2). История с 2019 года импортирована из текстовых PDF и фото-протоколов VK (см. архитектуру).
