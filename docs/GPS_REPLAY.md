# Часы, треки и реплей забега

Исследование от 26.07.2026. Отвечает на вопрос: можно ли связать сайт с часами участников
(Coros, Garmin, Strava) и показать, **как** человек бежал — не только итоговое время, а движение
по трассе; в пределе — все участники одновременно, точками, догоняя друг друга.

**Вывод одной строкой:** API часов для этого проекта закрыты (юридически и организационно) —
причём у Strava запрет держится даже для собственных данных, если их видит кто-то ещё, — но
самая сильная часть идеи — реплей забега — **не требует ни одного гаджета**: в базе уже лежит
достаточно данных, а SVG-геометрия трассы уже построена из GPX. GPX участников — приятный
апгрейд поверх, но не фундамент.

### Если читать только пять строк

1. **Реплей забега можно сделать прямо сейчас**, ни у кого ничего не спрашивая: отсечки
   2,3 км и 5 км + уже готовая `COURSE_RUN_PATH` дают позицию каждого участника в любой
   момент времени. 100% покрытия, ноль новых данных. → раздел 2
2. **API часов не дадут ничего.** Strava запрещает показывать данные атлета кому-либо, кроме
   него самого — и для собственных данных исключения нет; Garmin не пускает; Coros отбирает
   по размеру рынка. Всем троим нужен сервер. → раздел 1
3. **Приложения, читающие Страву, существуют и не нарушают** — они показывают тебе твои же
   данные после логина. Сломалось ровно то, что похоже на нас: групповые лидерборды. → раздел 1
4. **Файловый путь — не компромисс, а единственный законный** для публичной страницы.
   Ручной экспорт GPX/FIT — это не API, соглашение на него не распространяется. → раздел 3
5. **«Начать с Coros» переворачивается:** через API это самый трудный путь, а через файл
   Coros закрывается в первый же день — вместе с Garmin, Polar и Strava. → раздел 4

Порядок действий — в конце, в разделе «Порядок внедрения».

> **Дополнение от 26.07.2026 (вечер).** Всё выше написано про **публичную** страницу: трек одного
> человека видят все. Если поставить условие «данные никуда не загружаются, лежат локально у
> каждого в своём браузере и видны только владельцу» — юридический вывод переворачивается, а
> два технических утверждения этого дока оказались просто неверными (у Strava и у Coros CORS
> открыт, сервер не нужен). Разбор — в новом разделе 7 «Локальный авто-синк в браузере».

## 1. Почему API часов — тупик (проверено 26.07.2026)

### Strava — юридически запрещает ровно то, что нужно

Обновлённое API Agreement прямо запрещает показывать данные атлета кому-либо, кроме него самого:
данные, полученные от конкретного пользователя, могут отображаться в приложении **только этому
пользователю**. Совместный реплей чужих треков, общая карта, лидерборд по данным из Strava —
всё это нарушение соглашения, а не серая зона. Дополнительно с 2026 года:

- API-доступ требует активной платной подписки Strava у разработчика (~$11.99/мес);
- часть эндпоинтов выводится из эксплуатации (grace period 90 дней);
- запрещено использовать данные для обучения ML-моделей.

#### «Но ведь куча приложений читает Страву» — да, и они не нарушают

Возражение верное, и различие тут не в том, кто читает, а в том, **кто видит результат**.
Читать Strava можно и нужно — запрещено показывать данные одного человека другому.

- **Живут и прекрасно себя чувствуют:** Elevate, Intervals.icu, Runalyze, Smashrun,
  Statshunters, apps for Strava. Логика у всех одна: ты залогинился — ты видишь **свои**
  данные. Это ровно тот случай, который соглашение разрешает. Strava оценивала, что изменение
  затронет менее 0,1% приложений.
- **Сломалось именно то, что похоже на нас:** групповые лидерборды VeloViewer, лидерборды
  Zwift, режим «тренер видит спортсмена» в Intervals.icu. Всё, где данные одного показывались
  другому.

Наш случай — не просто в запрещённой категории, а в самом жёстком её углу: не залогиненный
тренер смотрит своего подопечного, а **полностью публичная страница вообще без логина**.

Про правоприменение честно: Strava давит отзывом ключа, и в основном по крупным приложениям —
клубный сайт на 40 человек, скорее всего, никто не заметит. Но это значит «строим витринную
фичу на правиле, которое сознательно нарушаем, и однажды она умирает вместе с ключом».
Фундамент так себе.

**И главное — спор беспредметен:** ручной экспорт даёт тот же самый файл. Весь вопрос стоит
о том, чтобы сэкономить один клик в неделю.

#### Легальный Strava на публичной странице всё-таки есть — но не тот

Официальные **embed-виджеты** (`strava-embeds.com/embed.js`, активность или маршрут) как раз
предназначены для публичных сайтов: рендерит их сама Strava, и под запрет API Agreement они
не подпадают. Требуют публичной приватности профиля и активности.

Почему нам не подходит: это внешний скрипт (у нас правило самодостаточности и офлайн-PWA),
это карта Strava в её оформлении, а не наша трасса, это по сути тот самый увод на чужой сервис,
и в январе 2026 виджеты у людей массово отваливались без изменений с их стороны. Как запасной
вариант «показать один красивый трек» — годится; как фундамент реплея — нет.

#### «А если через Strava, но лично для себя?» — проверено отдельно

Соблазнительная лазейка: подключить только свой аккаунт, свои же данные показывать себе же —
формально ровно то, что соглашение разрешает. У Strava для этого даже есть штатный режим:
новые приложения по умолчанию заводятся в **single player mode**, где авторизоваться может
только аккаунт самого разработчика. Технически — просто.

**Но на публичной странице это всё равно нельзя.** Ограничение написано про поверхности
приложения, а не про право собственности на данные: «Strava Data provided by a specific user
can only be displayed or disclosed in your Developer Application to that user». Как только
трек попадает на страницу протокола, которую открывают другие, — он показан не только тому
пользователю, чьи это данные. Исключения для «своих собственных данных разработчика» в
соглашении **нет** (проверено по тексту 2026 года). Плюс поверх этого — обязательная подписка
разработчика ради одного трека в неделю.

Итог: **API Strava годится только для приватной панели, которую вижу я один** — а хочется
как раз обратного, точки на общей карте забега.

#### Зато ручной экспорт — полностью чистый путь

Скачать свой GPX/FIT из веб-интерфейса Strava («Export GPX» / «Export Original») — это **не
API**, и API Agreement на него не распространяется вовсе. Ты не разработчик, получающий чужие
данные через платформу, — ты атлет, забирающий собственную запись. Опубликовать её на своём же
клубном сайте — твоё право как владельца данных.

То же самое верно для выгрузки напрямую из Coros app, Garmin Connect и Polar Flow.

**Следствие, которое переворачивает выбор:** файловый путь — не просто проще OAuth. Для всего,
что попадает на публичную страницу, он **единственный законный**. OAuth здесь покупает не
удобство, а запрет.

### Garmin — доступ не самообслуживаемый

Connect API (Activity API) выдаётся только одобренным партнёрам: не «зарегистрировал приложение
и получил client_id», а заявка с ручным бизнес-ревью на недели. По состоянию на 2026 год приём
новых заявок фактически приостановлен, публичной формы нет. Для клубного сайта на 20 человек
шансов нет.

### Coros — заявка на партнёрство, отбор по размеру рынка

Open API существует, но выдаётся по заявке, и Coros прямо пишет, что не может дать доступ всем:
при отборе смотрят на размер рынка приложения и характер использования данных. Реалистичный
исход для нас — отказ или молчание.

### Плюс архитектурный барьер

Любой OAuth требует обмена кода на токен с `client_secret` — то есть сервера. Сайт статический
(GitHub Pages, БД — закоммиченный SQLite, публикация через коммит). Пришлось бы заводить хотя бы
Cloudflare Worker (см. `BACKEND_HOSTING.md`) — а ради этого нужно, чтобы на другом конце было
что-то стоящее. Его нет.

**Итог:** ни одна из трёх экосистем не даёт того, что нужно. Дальше — только то, что мы можем
сделать своими данными и добровольно принесёнными файлами.

## 2. Реплей забега без единого гаджета (главная идея) 🔥

### Данных уже достаточно

Забег — общий старт. В `results` на каждого финишёра есть:

- `time23` — отсечка 2,3 км (конец первого большого круга), покрытие ~70% строк;
- `time5` — итог 5 км;
- `total_ms`, `gender`, `place_m` / `place_f`.

Три опорные точки на дистанции: `(0 м, 0)`, `(2300 м, t23)`, `(5000 м, t5)`. Этого хватает,
чтобы поставить каждого участника на трассу в любой момент времени. Там, где отсечки нет —
прямая от старта до финиша (ровный темп), и это честно помечается в UI.

### Геометрия уже построена

`scripts/build-course-track.ts` + `src/app/features/home/course-track/course-geometry.constant.ts`
дают ровно то, что нужно для реплея:

- `COURSE_RUN_PATH` — все 5 км в порядке бега одним подпутём (для `offset-path`);
- `COURSE_LAP_ONE_END_FRACTION = 0.4495`, `COURSE_LAP_TWO_END_FRACTION = 0.9078` — куда попадает
  отсечка 2,3 км по длине пути;
- `COURSE_START_POINT` / `COURSE_FINISH_POINT`, `COURSE_VIEW_BOX`.

То есть перевод «пройдено X метров» → «точка на экране» уже решён и уже используется на главной.
Реплей — это тот же маркер, только их N штук и они управляются временем, а не скроллом.

### Математика позиции

1. Дистанция от времени: монотонная интерполяция (PCHIP / monotone cubic) по трём опорным точкам —
   чтобы смена темпа выглядела плавно, но отсечки соблюдались точно. Линейная тоже работает,
   но на 2,3 км будет заметный «щелчок» скорости.
2. Дистанция → доля пути: делим на 5000 и берём точку на `COURSE_RUN_PATH` через
   `getPointAtLength()` (SVG) — один раз предсчитать таблицу длин, дальше бинарный поиск.
3. Кадр: `requestAnimationFrame`, позиция от «времени забега», а не от реального.

Точки между отсечками — интерполяция, а не факт. Это надо прямо написать в интерфейсе: сайт
уже держит планку честности с данными (в `course-geometry.constant.ts` отдельно оговорено, что
показываются заявленные дистанции, а не намеренные GPS).

### Что это даёт визуально

Негативный сплит перестаёт быть значком в таблице и становится зрелищем: человек с индексом
`pace2/pace1 < 1` на втором круге буквально отыгрывает соперников на глазах. Уже посчитанный
`core/history/pacing.ts` получает свою витрину.

### Связки с тем, что уже есть

- **«Выбери себя»** — своя точка крупнее и своего цвета, остальные приглушены.
- **Пикер друзей из bump-chart** (`features/records/bump-chart/`) — тот же паттерн поиска и
  подсветки, переиспользуется один в один.
- **`/vs`** — режим дуэли: два бегуна на трассе, между ними тянется резинка разрыва.
- **`place-gaps.ts`** — счётчик «+0:12 до следующего» вживую по ходу реплея.
- **Протокол** — кнопка «Смотреть забег» в шапке страницы события.

### UX-минимум

Play/pause, скорости ×1 / ×10 / ×60 (5 км за 30 секунд — норма для просмотра), скраббер по
времени, боковой лидерборд, который переупорядочивается на обгонах, deep-link на момент
(`?t=12:30`). Ленивый чанк — реплей не должен утяжелять главную.

### Оценка

Средняя по объёму фича, целиком на существующих данных и существующей геометрии. Самое
дорогое — не расчёт, а анимация и лидерборд. Ноль новых данных, ноль зависимостей, 100%
покрытия участников с первого дня.

## 3. GPX как апгрейд точки (ручная загрузка) ⭐

Когда реплей уже есть, GPX превращает интерполированную точку в настоящую — и это отличный
мотиватор («залей трек — и ты поедешь по-честному»).

### Какими часами бегут у нас

По наблюдениям организатора: Garmin, Polar, Coros — вразнобой, а вот **в Strava сидят почти все**,
независимо от марки часов. Это ключевой практический факт, и он играет в обе стороны:

- Strava — единственный общий знаменатель, поэтому именно её API было бы логично использовать —
  и именно она это запрещает (см. раздел 1);
- зато **инструкция для участников становится одна на всех**: «Strava → своя тренировка →
  ⋯ → Export GPX». Не четыре инструкции по маркам, а одна, которую поймёт любой. Ручной экспорт
  из Strava своей же тренировки — это не API и под API Agreement не подпадает.

Для тех, кто в Strava не заходит, остаются родные приложения: Garmin Connect, Polar Flow,
Coros app, Suunto — у всех есть экспорт GPX/FIT.

### Ручная загрузка — единственный универсальный способ

Файл участник отдаёт сам — это его данные, добровольно переданные клубу. Ни OAuth, ни API,
ни чужих ToS. Парсер должен принимать и **GPX, и FIT** (Garmin и Coros охотнее отдают FIT;
Strava-экспорт — GPX).

### Привязка ко времени — узкое место, но оно решено

Часы стартуют не по выстрелу. Нужен якорь:

- **лучший вариант:** `/timer` уже пишет `startedAtEpochMs` (см. `core/timer/session-actions.ts`) —
  это настоящий момент старта по стенным часам. Разница между ним и первой точкой GPX = сдвиг;
- **запасной:** подгонять так, чтобы продолжительность трека совпала с официальным временем,
  а пересечение линии старта детектировать геометрически.

### Приведение к трассе

- ресемплинг в 1 Гц (у Garmin бывает smart recording с переменным шагом);
- проекция в ту же нормализованную систему координат, что и `build-course-track.ts`;
- **снап на `COURSE_RUN_PATH`** с монотонным прогрессом — иначе GPS-шум уводит точки в кусты и
  обгоны читаются как каша. Сырой трек оставить опцией для личной карты одного человека;
- расхождение дистанции (часы намеряли 5,08 км) снимается тем, что позиция считается в **долях
  пути**, а подписи остаются официальными.

### Хранение — мимо основной БД

Трек — это ~1000–3000 точек. Даже в encoded polyline это ~10 КБ на человека; 20 человек × 50
забегов = порядка 10 МБ. В `protocol.db` этому не место: база тянется range-запросами, и рост
её тела бьёт по всем страницам (см. `PERF_DB_REQUESTS.md`), плюс бюджеты бандла.

Правильно: отдельные ассеты по событию — `tracks/2026-07-26.json`, которые грузятся **только**
при открытии реплея. В БД — максимум флаг «для этого забега есть треки» в `meta` или колонка у
`events`, чтобы не ходить за 404.

### Приватность — жёстко

GPX часто начинается у подъезда. При импорте:

- обрезать по временно́му окну забега и по геозоне парка;
- выбросить пульс, каденс, температуру, серийник устройства;
- время хранить относительным (мс от старта), а не абсолютным;
- согласие спрашивать явно, удаление своего трека — по запросу.

Скрипт `build-course-track.ts` уже написан с этой установкой («Nothing personal is read») —
держать ту же планку.

## 4. Кнопка «Подключить Coros» — лестница трения

Отдельно разобран запрос «не хочу возиться с файлом, хочу нажать кнопку один раз, и дальше
мои тренировки подтягиваются сами». Ниже — все уровни, от того, что можно сделать сегодня,
до настоящей одной кнопки, с честной ценой каждого.

### Уровень 0 — админский dropzone (для себя, ноль работы) ✅ инфраструктура уже есть

На `/admin` уже есть общий dropzone, куда кладётся xlsx-протокол. Положить рядом свой `.fit`
из Coros — это ноль нового UX. Для «хочу видеть, как я бежал» лично мне — это финальный ответ,
дальше можно не идти вообще. Работа только в парсере и отображении.

### Уровень 1 — публичная страница загрузки

Обычный `<input type="file">` на странице забега, парсинг **в браузере** (файл никуда не
уходит до подтверждения). Работает для Coros, Garmin, Polar, Suunto, Strava — для всех сразу,
одинаково. Ни заявок, ни секретов, ни сервера.

### Уровень 2 — PWA Share Target: «Поделиться → Воскресный пробег»

Сайт уже PWA (ngsw, install-prompt в `features/timer/install-prompt/`). Манифестный
`share_target` регистрирует установленное приложение в системном меню «Поделиться»: в приложении
Coros жмёшь «экспорт → поделиться → Воскресный пробег», файл прилетает на сайт. Два тапа вместо
шести.

**Оговорка, важная лично для Алексея:** на Android это работает, на **iOS Safari приём шеринга
не поддерживается** — там останется обычный выбор файла через «Файлы». То есть Share Target —
это подарок андроидной части клуба, а не универсальное решение.

### Уровень 3 — Coros Open API напрямую ⚠️ маловероятно

- Доступ выдаётся **по заявке с ручным ревью**; Coros прямо пишет, что не может дать доступ
  всем, и при отборе смотрит на размер рынка приложения. Клубный сайт на 40 человек — почти
  гарантированный отказ или молчание.
- Даже при одобрении OAuth2 требует обмена кода на токен с `client_secret` → нужен сервер.
  Минимум — Cloudflare Worker (см. `BACKEND_HOSTING.md`), плюс хранение и ротация refresh-токенов,
  а хранить их на статике негде.

### Уровень 4 — агрегатор (Terra, Spike и подобные) — настоящая «одна кнопка»

Единственный реалистичный способ получить именно то, что хочется. У агрегаторов **уже есть
партнёрский доступ** к Coros, Garmin, Polar, Suunto — то есть проблема одобрения решена ими,
а не нами. Одна OAuth-кнопка покрывает все марки сразу, новые тренировки прилетают вебхуком.
У Terra есть бесплатный тариф, и Coros в него входит.

Цена: всё равно нужен сервер (приёмник вебхуков + секрет), появляется внешняя коммерческая
зависимость у хобби-проекта, и данные, пришедшие через агрегатор **из Strava**, всё равно
остаются под запретом Strava на показ третьим лицам (данные напрямую из Coros/Garmin/Polar —
не под ним).

### Чего делать нельзя

Неофициальный Coros API по email и паролю (`xballoy/coros-api` и подобные) — это вход в
непубличный бэкенд Training Hub. Просить **участников** отдать пароль от аккаунта часов нельзя
ни при каких условиях, а сломаться он может в любой день.

> **Поправка от 26.07.2026 (вечер):** здесь раньше стояло «вдобавок из браузера это не сработает
> из-за CORS» — это неверно. Проверено curl'ом: `teamapi.coros.com` и `teameuapi.coros.com`
> отражают `Origin`, разрешают `POST` и заголовок `accesstoken`. Из браузера вызывается напрямую,
> прокси не нужен. Причина не делать это публично — пароль и непубличный API, а не техника.
> Личный локальный сценарий разобран в разделе 7.

### Три вывода, которые меняют план

1. **«Начнём с простого — с Coros» на деле переворачивается.** Coros через API — самый
   трудный путь из всех (заявка + сервер + токены). А файловый путь покрывает Coros **в первый
   же день** и заодно бесплатно даёт Garmin, Polar и Strava. Простое здесь — это файл, а не марка.
2. **OAuth не даёт авто-привязки бесплатно.** Даже с токеном тренировку надо сопоставить с
   забегом по времени старта и геозоне парка — и этот матчинг одинаково нужен в файловом
   варианте. OAuth экономит только сам импорт файла, то есть порядка 30 секунд раз в неделю
   на человека.
3. **Экономика.** Ради этих 30 секунд — сервер, секреты, ротация токенов, партнёрское
   одобрение и постоянное обслуживание. При том, что треки реально понадобятся человекам
   пяти-десяти. Уровни 0–2 делаются за вечер и работают для всех марок.

**Рекомендация:** 0 → 1 → 2. Уровень 4 — только если наберётся 10+ человек, которые реально
хотят подключиться и спрашивают сами. Уровень 3 не пробовать вообще.

## 7. Локальный авто-синк в браузере (проверено 26.07.2026, вечер) 🔥

Постановка задачи, из-за которой раздел появился: **человек один раз подключает свой аккаунт,
дальше его тренировки подтягиваются сами, прямо в браузере, и остаются у него на устройстве.**
На сайт ничего не загружается, у каждого свои данные в своём `localStorage` (или IndexedDB),
чужих треков никто не видит. Нужно это ради одного — посмотреть анимацию: где и как он бежал,
со скоростью и временем.

Это **другая фича**, чем разделы 1–4. Там трек ехал на общую страницу протокола, и именно это
всё ломало. Здесь он не покидает устройство.

### 7.1 Условие «локально» снимает главный запрет

Формулировка Strava: «Strava Data provided by a specific user can only be displayed or disclosed
in your Developer Application **to that user**». Трек, который лежит в браузере владельца и
показывается владельцу, — это ровно разрешённый случай, тот же, в котором живут Elevate,
Intervals.icu и Runalyze (см. раздел 1). Запрещённым он становится в момент, когда попадает в
`data/`, в репозиторий или на страницу забега, которую открывает кто-то другой.

**Практический вывод:** граница проходит не по источнику данных, а по тому, куда трек попадает.
Локальная личная панель — можно. Точки всех участников на общей карте реплея — нельзя (для
данных из Strava; для файла, который человек сам отдал клубу, — можно, раздел 3).

### 7.2 Проверено вживую: сервер не нужен, CORS открыт у обоих

Раздел 4 утверждал, что любой OAuth упирается в `client_secret` и, значит, в сервер, а
неофициальный Coros из браузера не вызвать из-за CORS. Проверка curl'ом 26.07.2026:

```
OPTIONS https://www.strava.com/oauth/token          → 200, access-control-allow-origin: *
                                                       access-control-allow-methods: POST
GET     https://www.strava.com/api/v3/athlete       → 401, access-control-allow-origin: *

OPTIONS https://teameuapi.coros.com/activity/query  → 200, access-control-allow-origin: <Origin>
   (Origin: https://sundayrun.example)                 access-control-allow-methods: POST
                                                       access-control-allow-headers: content-type, accesstoken
                                                       access-control-allow-credentials: true
```

То же самое у `teamapi.coros.com`. Значит:

- **обмен `code → access_token` у Strava делается прямо из браузера** — сервер нужен не для
  протокола, а только чтобы спрятать секрет;
- **Coros Training Hub API вызывается из браузера напрямую**, `cors-anywhere` и любой другой
  прокси не нужны.

### 7.3 Coros напрямую (выбран как основной вариант)

Протокол снят с `xballoy/coros-api` (папка `api/*.bru`) — библиотека нужна как **описание**,
подключать её незачем: это NestJS-CLI под Node, а в браузере это три `fetch`.

```
POST {API}/account/login
     { "accountType": 2, "account": "<email>", "pwd": "<MD5(password) в hex>" }
     → { result: "0000", data: { accessToken, ... } }

GET  {API}/activity/query?size=200&pageNumber=1&from=20260101&to=20261231&modeList=100
     header: accessToken: <token>
     → список активностей: labelId, sportType, дистанция, дата, время

POST {API}/activity/detail/download?labelId=<id>&sportType=100&fileType=1
     header: accessToken: <token>
     → { data: { fileUrl: "https://…" } }        fileType: 1=gpx, 3=tcx, 4=fit, 2=kml, 0=csv
```

Регионы (`{API}`): `teameuapi.coros.com` — Европа (аккаунт на `trainingeu.coros.com` — этот),
`teamapi.coros.com` — глобальный, `teamcnapi.coros.com` — Китай. `modeList=100` — «Run»
(`102` — трейл, `103` — стадион), даты в формате `YYYYMMDD` — то есть **фильтр «только
воскресенья нужных дат» делается на стороне Coros**, а не перебором 667 активностей.

**Что здесь хорошо:** ни подписок, ни заявок, ни OAuth-редиректов, ни `client_secret`; отдаёт
готовый GPX/FIT; данные — с тех самых часов, что на руке; всё в три запроса.

**Непроверенное звено ровно одно.** `fileUrl` ведёт на CDN, и неизвестно, отдаёт ли **он** CORS.
Разведка по вероятным хостам: `oss.coros.com` (Alibaba OSS) отвечает `access-control-allow-origin: *`
для GET — оттуда файл заберётся; `static.coros.com` (S3) на пробу с `Origin` заголовков не вернул —
оттуда нет. Какой из них реально в `fileUrl`, видно только с живым аккаунтом: открыть
`trainingeu.coros.com`, нажать «Экспорт данных» (кнопка уже есть в UI) или скачать одну
активность и посмотреть в devtools → Network адрес файла, затем
`curl -I -H "Origin: https://x.dev" <fileUrl>`.

**Запасной путь, если CDN закрыт:** страница детали активности (`/activity-detail?labelId=…`)
рисует карту и график темпа из **JSON**, а не из GPX — значит есть эндпоинт вида
`/activity/detail/query`, отдающий точки трека прямо в ответе, и он лежит на том же
`teameuapi.coros.com`, у которого CORS уже проверен. Его имя и параметры снимаются из devtools
за минуту. Для анимации такой JSON даже удобнее файла.

**Чем платим:**

- это **непубличный API**: сломается — узнаем по факту, никаких гарантий и никакого changelog;
- нужен **пароль от аккаунта Coros**. Себе — вопрос личного выбора; хранить его в `localStorage`
  не нужно ни в каком виде: пароль вводится один раз за сессию, наружу уходит только его MD5,
  а сохранять имеет смысл лишь `accessToken` (срок жизни неизвестен — выяснится опытом);
- **участникам это предлагать нельзя** — см. раздел 4, «Чего делать нельзя». Просить у людей
  пароль от аккаунта часов недопустимо, даже если код честно никуда его не отправляет: научить
  человека вводить свой пароль на постороннем сайте — плохая привычка сама по себе.

**Нулевой вариант, работающий уже сегодня:** кнопка «Экспорт данных» в самом Training Hub —
выгрузка активностей без единой строки кода. Дальше — та же дропзона, что для протокола
(`features/upload/protocol-dropzone/`), и `fflate` для ZIP, который в зависимостях уже есть.

### 7.4 Strava: «каждый заводит своё приложение» (разобрать отдельно — запрос от 26.07)

Идея: не заводить один общий app с секретом в бандле, а дать каждому завести **свой**
и вставить пару `client_id` / `client_secret` у себя на странице. Тогда секрет живёт в
`localStorage` конкретного человека, общего секрета нет вообще, сервера нет вообще.

**Как это выглядит для человека:**

1. `strava.com/settings/api` → создать приложение (имя, категория, иконка, **Authorization
   Callback Domain** = домен сайта);
2. скопировать `client_id` и `client_secret` в поле на нашей странице → они уходят в
   `localStorage`, никуда больше;
3. кнопка «Подключить» → редирект на `strava.com/oauth/authorize?...&scope=activity:read`
   → возврат с `code`;
4. браузер сам меняет `code` на токены (`POST /oauth/token`, CORS открыт — см. 7.2),
   `access_token` живёт 6 часов, дальше обновляется по `refresh_token`.

**Данные.** GPX Strava по API **не отдаёт** (`/export_gpx` — веб-роут под сессионную куку, не под
токен). Вместо него `GET /activities/{id}/streams?keys=latlng,time,distance,velocity_smooth,altitude&key_by_type=true`
— и это **лучше GPX**: время и скорость приходят по точкам готовыми, ровно то, что нужно
анимации. Отбор нужных тренировок: `GET /athlete/activities?after=&before=` по датам забегов
из `events` + `type: Run` + дистанция 4,5–6 км.

**Цена и правила (проверено 26.07.2026):**

- **Standard tier требует активной подписки Strava** — $11.99/мес; это обычная подписка, а не
  надбавка разработчика: «the Strava subscription provides you access to the API — there is no
  additional fee». Считается **на разработчика**, не на приложение. Действует с 30.06.2026;
- отсюда главный минус схемы: **своё приложение = своя подписка у каждого**. Для одного человека,
  который и так платит Strava, это ноль. Для клуба — фильтр, который пройдут единицы;
- новые приложения стартуют с доступом на одного атлета; до 10 атлетов теперь **self-upgrade**
  из дашборда без ревью (то есть один общий app на 10 человек формально возможен — но тогда
  секрет снова общий и требует сервера, см. 7.2);
- лимиты: 200 запросов / 15 мин, 2000 / сутки — при ~50 забегах не ограничение;
- сентябрь 2026: выпилены Club Activities / Club Members / Segments Explore; streams живы;
- к 01.06.2027 обязательная миграция: base URL `https://www.api-v3.strava.com`, токен в заголовке;
- бренд-гайдлайны: «Powered by Strava», ссылка на активность, никакого намёка на аффилиацию.

**Безопасность.** `client_secret` в `localStorage` — это секрет владельца, лежащий на устройстве
владельца, и риск он несёт только сам: любой XSS на нашем сайте даёт доступ на чтение его
Strava. Смягчения: `scope=activity:read` (без `activity:read_all` и без записи), после обмена
хранить только `refresh_token`, держать всё под отдельным ключом, дать кнопку «Отключить»
(чистка ключа + `POST /oauth/deauthorize`).

**Честная оценка трения.** Завести приложение — это 5 минут и понимание слов «callback domain».
Для Алексея приемлемо; для среднего участника клуба — стена. То есть схема «каждый со своим
app» хороша как **личный** инструмент и плоха как клубная фича — что совпадает с условием
«локально, у каждого своё» и потому здесь не противоречие.

### 7.6 Блокер в нашем коде — важнее выбора источника

`scripts/build-course-track.ts` **намеренно уничтожает геопривязку**: проекция делается
equirectangular вокруг центра бокса трека, результат нормируется в `VIEW_SIZE = 1000` и
леттербоксится, а в `features/home/course-track/course-geometry.constant.ts` уезжают только
viewBox-единицы (`COURSE_RUN_PATH` — 167 точек, `COURSE_LAP_*_END_FRACTION`, `COURSE_MARKS`).
Ни `lat0/lon0`, ни масштаба, ни накопленных метров (`metersIn`) наружу нет — так и было
задумано ради приватности.

**Следствие: спроецировать чужой трек на нашу карту сейчас нечем.** Любой сценарий из 7.3 и 7.4
упирается в это первым. Нужен экспорт «якоря» — `{ lat0, lon0, scale, offsetX, offsetY }`, пять
чисел, персональных данных не содержащих (это параметры проекции, а не точки трека). Заодно
имеет смысл выгружать массив точек с накопленной длиной, чтобы не парсить строку `d` в рантайме
и не звать `getPointAtLength()` на каждый кадр.

Всё остальное уже готово: механика реплея расписана в разделе 2, `fflate` (ZIP) в зависимостях,
дропзона переиспользуема, паттерн device-local сервиса — `state/self-athlete.service.ts`.

### 7.7 Где хранить

- **Нормализованный трек** — это ~1000–1500 точек по три числа (`x`, `y`, `t`); в JSON порядка
  10–30 КБ на забег. Полсотни забегов уложится в `localStorage` (лимит ~5 МБ на origin), и
  тогда новый сервис пишется ровно по существующему паттерну (`sundayrun.tracks.v1`,
  сигнал + защитный `readStored`, SSR-noop-хранилище).
- **Сырые файлы** (GPX/FIT как есть) в `localStorage` не поместятся — 5 км GPX это ~300 КБ XML.
  Если хранить сырьё, нужен IndexedDB (в проекте пока не используется нигде).
- Рекомендация: **хранить только нормализованное** — точки в системе координат трассы, время
  относительное от старта, без пульса, каденса, температуры и серийника устройства. Тогда
  `localStorage` достаточно, и приватность соблюдена «по построению», как в разделе 3.
- В `data/sundayrun.db` не попадает **ничего** — ни трека, ни флага, ни факта подключения.
- Парсер и страница — за `loadComponent`: бюджет initial 1,5 / 1,8 МБ, а FIT-парсер тяжёлый.

### 7.8 Что решать

Оба пути технически подтверждены и оба дают ровно то, что просили: авто-синк в браузере с
хранением у пользователя. Разница не в технике, а в цене:

|                     | Coros напрямую               | Strava, своё приложение у каждого              |
| ------------------- | ---------------------------- | ---------------------------------------------- |
| Деньги              | нет                          | подписка $11.99/мес **у каждого**              |
| Настройка человеком | e-mail + пароль              | завести app, скопировать 2 значения            |
| Легальность         | серая зона (непубличный API) | официально, при локальном показе — чисто       |
| Стабильность        | сломается без предупреждения | официальный API + миграция к 01.06.2027        |
| Данные              | готовый GPX/FIT/JSON с часов | streams: точки + время + скорость              |
| Покрытие клуба      | только владельцы Coros       | почти все (в Strava сидят независимо от марки) |
| Непроверенное       | CORS у CDN с файлом (7.3)    | —                                              |

Порядок, который выглядит разумным: сначала **7.6** (якорь проекции — нужен в любом случае),
потом личная карта одного забега из файла (раздел 5) как обкатка отрисовки, и только потом
авто-синк тем источником, который выберется.

---

## Порядок внедрения

1. **Реплей забега из отсечек** — вау без новых данных, на готовой геометрии. Делать первым.
2. **Личная карта по своему GPX/FIT**, файл кладётся через существующий админский dropzone —
   обкатка парсинга и приватности на одном человеке, без нового UX.
3. **Публичная загрузка файла** — та же механика, открытая всем; сразу все марки.
4. **GPX апгрейдит точку в реплее** — когда первые три шага живут.
5. **PWA Share Target** — «поделиться» из приложения часов; Android да, iOS нет.
6. **Ссылка на профиль** — по запросу, не раньше.
7. **Агрегатор (Terra) ради «одной кнопки»** — только при живом спросе от 10+ человек;
   требует сервера и внешней зависимости.
8. **Прямой OAuth / API часов ради публичной страницы** — ✖ не делать: Strava запрещает по
   существу, Garmin не пускает, Coros отбирает по размеру рынка.
   ⚠️ Уточнение от 26.07.2026 (вечер): формулировка «и всё это требует сервера» неверна —
   у Strava и Coros CORS открыт, из браузера работает (раздел 7.2). И для **локальной личной**
   панели, где трек не покидает устройство, прямой API — единственный способ авто-синка и
   запретом не покрыт. Порядок для этой ветки — в разделе 7.8.
9. **Якорь проекции в `build-course-track.ts`** (`lat0/lon0/scale/offset`) — предусловие любого
   импорта чужого трека, от источника не зависит. Раздел 7.6.

## Открытые вопросы

- Реплей всех сразу или только «своих» (себя + друзей)? На 40 участниках все сразу читаемо,
  на 150 — нет; нужен порог и фильтр.
- Отдаёт ли CORS тот CDN, на который ведёт `fileUrl` у Coros (`oss.coros.com` — да,
  `static.coros.com` — нет)? Проверяется за минуту с живым аккаунтом, раздел 7.3.
- Как называется эндпоинт детали активности Coros, из которого страница `activity-detail`
  рисует карту и темп? Он на уже проверенном хосте и удобнее файла.
- Сколько живёт `accessToken` Coros и есть ли refresh — в документации, которой нет, ответа тоже нет.
- Что делать с DNF: снимать точку с трассы в момент схода или довозить пунктиром?
- Показывать ли реплей для забегов без отсечек (только старт-финиш) — там все бегут ровно и
  обгонов нет, зрелище слабое. Возможно, скрывать кнопку.
- Реплей как GIF/видео для шеринга — заманчиво, но тяжело; сначала deep-link на момент.
