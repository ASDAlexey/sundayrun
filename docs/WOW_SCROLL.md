# WOW-скролл: сценарий первого впечатления

Документ-задумка. **Тир 1 (§8) реализован** — см. отметки «✅ сделано» ниже. Остальное пока план.

- **Часть I (§1–10)** — скролл и анимация: как страница ведёт себя, пока по ней листают.
- **Часть II (§11–17)** — нативные ощущения и фичи-истории: хаптика, гироскоп, шеринг, реплей забега;
  разные возможности iOS и Android.

## 1. Контекст и цель

Основной сценарий первого контакта — **мобильный**: человек в Telegram или MAX жмёт ссылку, попадает
на `/` в in-app браузере, скроллит один-два экрана и решает, приходить ли в воскресенье. У нас есть
примерно **8 секунд** и **два свайпа**, чтобы это выглядело не как «сайт районного мероприятия», а
как продукт.

Что должно случиться в голове у человека:

1. **0–1 с** — «о, это красиво» (первый экран, ещё до скролла).
2. **1–4 с** — «здесь всё живое, за этим следят» (таймер тикает, счётчик до старта).
3. **первый свайп** — «ого» (главный эффект секции трассы).
4. **дальше** — «тут про меня»: последние забеги, цифры, своя статистика.

Ограничение, которое нельзя нарушать: **эффекты не должны мешать читать**. Это не промо-лендинг
разового ивента, сюда возвращаются каждую неделю за протоколом. Wow нужен на первом заходе; на
двадцатом он не должен раздражать.

## 2. Что уже есть

| Есть                                                                                 | Файл                                                       |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `ScrollReveal` — IntersectionObserver, вешает `.is-visible`                          | `src/app/shared/directives/scroll-reveal/scroll-reveal.ts` |
| `.reveal` — translateY(30px) + opacity, 0.8s `var(--ease)`, reduced-motion отключает | `src/styles/_animations.scss`                              |
| Токены времени и пружины: `--ease`, `--transition-time`, `--spring-tap`, `--time-*`  | `src/styles/_tokens.scss`                                  |
| Живой обратный отсчёт до старта                                                      | `src/app/features/home/next-start.ts`                      |

Слабые места текущего решения:

- Один и тот же эффект на всём — «выехало снизу». Это база, а не wow.
- Ревил **реверсивный**: при обратном скролле блоки гаснут. На мобиле при инерционном скролле вверх
  контент мигает. Для контентных секций нужен режим «показать один раз».
- Списки ревилятся **целиком одним блоком** (`home__latest-list` — один `appScrollReveal` на `<ul>`).
  Карточки должны выходить каскадом.
- Ни одного эффекта, привязанного к смыслу. Всё декоративно и одинаково.

## 3. Принципы

1. **Только `transform` и `opacity`.** Никаких анимаций `width/height/top/box-shadow` в скролле.
2. **Смысл важнее блеска.** Лучший эффект — тот, что объясняет содержание (маркер бежит по трассе),
   а не тот, что просто двигается.
3. **Один герой на экран.** На каждый вьюпорт — максимум один «громкий» эффект, остальное фоном.
4. **Мобильный бюджет.** In-app браузер на среднем Android: без `backdrop-filter` внутри
   скроллящихся слоёв, без больших `filter: blur()` на движущихся элементах, не больше ~6
   одновременно анимируемых узлов.
5. **`prefers-reduced-motion` — полноценный режим**, а не «выключили анимации». Контент должен быть
   виден целиком и сразу; смысловые эффекты (маркер на трассе) заменяются статичной финальной
   позицией.
6. **SSR-безопасность.** Никакой инициализации вне `afterNextRender`. Контент видим без JS —
   скрытое состояние `.reveal` живёт в CSS, но со страховкой (см. §7).
7. **Не трогаем LCP.** Заголовок первого экрана и блок «Следующий старт» не прячем и не анимируем
   на входе через opacity 0 → это прямой удар по LCP и по ощущению скорости.

## 4. Технический фундамент

### 4.1 CSS scroll-driven animations как основной инструмент

Главный переход: с JS-обсервера на **`animation-timeline: view()`**. Это даёт эффекты, привязанные к
позиции скролла (не «сработало/не сработало», а плавная интерполяция), и работает в компоузере без
JS вообще — то, что нужно на слабом телефоне.

```scss
@supports (animation-timeline: view()) {
  .reveal {
    animation: reveal-rise linear both;
    animation-timeline: view();
    animation-range: entry 10% cover 35%;
    transition: none; // JS-класс больше не нужен
  }
}
```

Fallback — существующий `ScrollReveal` + `.reveal` transition, без изменений. Директива при
поддержке `animation-timeline` может вообще не подписываться на обсервер (проверка в
`afterNextRender`), чтобы не держать лишние наблюдатели.

Поддержка на сегодня: Chrome/Edge 115+, Safari 26+, Firefox — за флагом. То есть значительная часть
мобильной аудитории (iOS < 26, Firefox) останется на fallback → **fallback обязан выглядеть
достойно сам по себе**, а не быть «версией без эффекта».

### 4.2 Каскад (stagger)

Индекс через CSS-переменную на элементе, задержка считается в CSS:

```html
@for (race of latestRaces(); track race.slug; let i = $index) {
<li class="home__latest-item" [style.--i]="i">…</li>
}
```

```scss
.home__latest-item {
  animation-delay: calc(var(--i) * 70ms);
}
```

Потолок задержки — `min(var(--i) * 70ms, 350ms)`, иначе последняя карточка длинного списка
выезжает через полсекунды после того, как её уже прочитали.

### 4.3 Что понадобится добавить

- Директива `appScrollReveal` получает входы: `once` (не скрывать обратно) и `variant`
  (`rise` | `fade` | `scale` | `mask`).
- Новый файл `src/styles/_scroll-effects.scss` с keyframes и `@supports`-блоками; `_animations.scss`
  остаётся базовым fallback-слоем.
- Утилита «число докручивается» (count-up) — отдельная директива на `requestAnimationFrame`,
  строго `font-variant-numeric: tabular-nums`, чтобы не дёргалась ширина.

## 5. Главная — сценарий по экранам

### Экран 1. Hero (без скролла)

Задача: за секунду показать, что сайт живой.

**5.1 «Рассвет 8:00» — атмосферный градиент.**
За заголовком — тёплое радиальное свечение (`--accent-atmosphere`), которое очень медленно
смещается при скролле (параллакс на псевдоэлементе, `translate3d`, коэффициент ~0.15). Дёшево,
работает даже на fallback через `scroll-timeline: scroll()`. Ощущение глубины без единого
изображения.

**5.2 Заголовок — появление по словам.**
«Воскресный / парковый / пробег» — три строки, каждая выезжает из-под маски (`clip-path`
или `overflow: hidden` + `translateY(100%)`) с задержкой 60 мс. **Только при загрузке, один раз**,
и не через `opacity: 0` на самом LCP-элементе, а через маску-обёртку — LCP не страдает.
Длительность 0.5 с, `var(--ease)`.

**5.3 Счётчик — перекидные цифры.**
Сейчас `00 07 29 28` просто меняет текст. Нужен **roll**: старая цифра уезжает вверх и гаснет,
новая приезжает снизу. Только для секунд и минут (часы/дни меняются редко — там ролл будет
незамеченной работой). Реализация: два слоя цифр в одном `overflow: hidden` контейнере,
`transform: translateY`, длительность `var(--time-tap)`.

Это самая ценная микроанимация на сайте: она доказывает, что страница живая, **до** любого скролла.

**5.4 Подсказка скролла.**
Тонкая вертикальная линия под hero, по которой раз в 2 с (`--time-breathe`) сверху вниз пробегает
светящаяся точка. Исчезает навсегда после первого скролла. На мобиле — обязательна: в in-app
браузере не всегда очевидно, что ниже что-то есть.

**5.5 Мобильный липкий мини-таймер.**
Когда карточка «Следующий старт» уходит вверх за экран, сверху выезжает узкая полоска
`до старта 07:29:28` (высота ~36px, фон `--surface`, без blur). Появление — по
`animation-timeline: view()` на самой карточке, ноль JS. Это одновременно эффект и польза:
таймер остаётся перед глазами всю страницу.

### Экран 2. Трасса — **главный wow**

Это единственное место, где стоит вложиться по-крупному, и единственное, где эффект несёт смысл:
**«5 км — два круга по парку»** можно не написать, а показать.

**5.6 Пробег маркера по трассе (scrollytelling).**

- Карта становится `position: sticky` на высоту ~180vh секции.
- Поверх карты — SVG-слой с траекторией трассы (один `<path>`, снятый по существующей схеме
  `course-5k.webp`).
- Линия трассы **рисуется** по мере скролла: `stroke-dashoffset` от полной длины до 0,
  `animation-timeline: view()`.
- По линии едет точка-бегун: `offset-path: path(...)` + `offset-distance: 0% → 100%`, привязанное
  к тому же таймлайну. Два круга = два прохода по контуру.
- Рядом с маркером — подписи, которые проявляются на своих отметках: `Старт/Финиш`, `1-й круг —
2,3 км`, `2-й круг`, `5 км`.

На мобиле: карта на всю ширину экрана, sticky сверху, текстовые факты (сбор, старт, ВК) проезжают
под ней. Это ровно та механика, которую люди видели в дорогих лендингах, и она здесь **уместна** —
человек буквально видит, куда ему бежать.

Реализация без внешних библиотек: чистый SVG + CSS scroll-driven animations. Fallback (Safari < 26,
Firefox): карта статична, линия трассы просто отрисована целиком, маркер стоит на старте, факты
ревилятся обычным `.reveal`. Ничего не сломано.

Оценка: это самый дорогой пункт документа (нужно снять path по карте, выверить sticky-высоту на
мобиле, не сломать существующий диалог «Открыть схему»). Но и отдача максимальная.

**5.7 Дешёвая альтернатива, если 5.6 окажется дорого.**
Карта появляется с лёгким `scale(1.06) → scale(1)` и маской-«шторкой» слева направо, а поверх один
раз пробегает световой блик. 20 минут работы, 20% эффекта.

### Экран 3. Твоя статистика

Секция и так персональная — усилить точечно.

**5.8** Плашки цифр выезжают каскадом (`--i`), значения **докручиваются** от 0 (0.9 с, `--ease`).
Время («лучшее время») не докручиваем цифрами — оно докручивается «по последнему разряду» или
просто проявляется: бегущее `24:31` выглядит как ошибка.

**5.9** Имя человека в заголовке — подчёркивание, которое прочерчивается слева направо при входе
секции в вид (`scaleX` на псевдоэлементе). Мелочь, но читается как «это про тебя».

### Экран 4. Последние забеги

**5.10 Каскад карточек** вместо одного блочного ревила (см. §4.2). Направление — снизу + едва
заметный `scale(0.98) → 1`.

**5.11 Свежий протокол.** Самая верхняя карточка при первом появлении получает однократный импульс
акцентной рамки (`--accent-line` → `--accent` → обратно, 0.6 с). Только если забег состоялся в
последние 7 дней.

**5.12 График посещаемости в карточке забега** (уже существует, «динамика 8 недель»): столбики
вырастают снизу каскадом при попадании карточки в вид. Дёшево (`transform: scaleY`, `transform-
origin: bottom`), выглядит дорого.

### Экран 5. За всю историю

**5.13 Count-up для крупных чисел** (забегов проведено, всего финишей, уникальных финишёров) —
здесь он максимально уместен, цифры большие и «набегают». 1.2 с, easing `--ease`, tabular-nums.

**5.14 Медианы М/Ж** — под каждым значением тонкая полоска, которая заполняется до
пропорциональной длины. Даёт мгновенное визуальное сравнение, которого сейчас нет.

### Финал страницы

**5.15 Финишная лента.** В самом низу — горизонтальная клетчатая полоса (чистый CSS-градиент),
которая «проявляется» на последних 10% скролла. Ставит точку: человек досмотрел до финиша. Дёшево
и тематически идеально.

## 6. Глобальные эффекты (все страницы)

**6.1 Полоска прогресса чтения** сверху под шапкой — `scroll-timeline: scroll(root block)`,
`transform: scaleX(0 → 1)`, цвет `--accent-gradient`. Ноль JS, ~10 строк CSS. Даёт ощущение
«современного сайта» на каждой странице.

**6.2 Сжимающаяся шапка на мобиле.** При скролле вниз шапка уменьшает высоту, логотип — масштаб,
фон становится плотнее. Через scroll-driven animation, без слушателей скролла. Освобождает
драгоценные пиксели вертикали на телефоне.

**6.3 Переходы между маршрутами.** Angular поддерживает View Transitions
(`withViewTransitions()` в роутере). Кросс-фейд между страницами + морфинг заголовка забега при
переходе с главной в протокол (`view-transition-name` на карточке и на заголовке `/race/:slug`).
Это ощущается как нативное приложение и стоит буквально одного флага плюс пары CSS-свойств.
**Проверить:** не конфликтует с виртуальными таблицами и с текущим `RouteErrorNotifier`.

**6.4 Тактильный отклик.** У нас уже есть `--spring-tap`. Стоит распространить пружину на все
кликабельные карточки (карточка забега, строка протокола) — на тач-устройстве это половина
ощущения качества.

## 7. Обязательные ограничения и риски

| Риск                                                                    | Мера                                                                                                                                       |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Контент невидим, если JS не выполнился (fallback-ветка)                 | Страховка: `html:not(.js) .reveal { opacity: 1; transform: none }` — класс `js` ставится в `app.config`                                    |
| SSR/pre-render                                                          | Вся инициализация только в `afterNextRender`; SSR-разметка должна отдавать финальное состояние                                             |
| Бюджет бандла (1.5/1.8 МБ; главная **не** ленивая)                      | Никаких библиотек анимации (GSAP/Lenis/Motion One). Только CSS + мелкие директивы. SVG трассы инлайнить оптимизированным, не более ~4 КБ   |
| Скролл-джанк в in-app браузере Telegram/MAX                             | Запрет `backdrop-filter` и `blur` на движущихся слоях; проверять на реальном среднем Android, а не в DevTools throttle                     |
| Sticky-секция трассы ломает адресную строку iOS (динамический viewport) | Высоты только в `dvh`, тестировать в Safari iOS с сворачивающейся панелью                                                                  |
| `prefers-reduced-motion`                                                | Отдельная ветка для каждого нового эффекта, а не общий выключатель                                                                         |
| Перегруз                                                                | Правило «один герой на экран». Если два эффекта борются за внимание — оба вырезаются                                                       |
| Существующие тесты                                                      | `_animations.scss` и `ScrollReveal` покрыты спеками; при переходе на `animation-timeline` спеки директивы переписать под ветку `@supports` |

Отдельно: **`will-change` не оставлять постоянно**. Сейчас в `.reveal` он висит всегда — на длинной
главной это десятки лишних композиторных слоёв на телефоне. Снимать после завершения или заменять
на `will-change: auto` в `.is-visible`.

## 9. Другие страницы — где ещё стоит вложиться

- **`/year` — «Итоги года».** Самый сильный кандидат после главной. Формат Spotify Wrapped:
  полноэкранные секции со скролл-переходами, крупные цифры, которые набегают, бейджи, которые
  влетают. Это страница, которой делятся в чатах — а значит, она сама себя распространяет.
- **`/athlete`.** Спарклайн «Формы» прочерчивается по скроллу (`stroke-dashoffset`). Прогресс-бар
  «Легенды трассы» заполняется при входе в вид. Мем-пороги — лестница, ступени которой
  подсвечиваются каскадом.
- **`/race` (протокол).** Осторожно: таблица на виртуальном скролле, каскад строк там будет
  дёргаться и стоить кадров. Ограничиться шапкой протокола и блоком погоды. Подиум (топ-3) —
  выезд трёх карточек с разной задержкой.
- **`/records`.** Bump chart: линии прочерчиваются слева направо при входе графика в вид. Один
  `stroke-dashoffset` на серию, каскад по индексу.
- **`/timer`.** Ничего не трогать. Это инструмент, там любая лишняя анимация — вред.

## 10. Как поймём, что получилось

- На среднем Android в in-app браузере Telegram скролл главной держит 60 fps (профайл Performance,
  а не «на глаз»).
- LCP и INP не хуже текущих (замер до/после через Lighthouse на mobile-профиле).
- `prefers-reduced-motion: reduce` — страница полностью читаема, ни один блок не остаётся скрытым.
- Сборка укладывается в бюджет; ни одной новой рантайм-зависимости.
- Субъективно: человек, впервые открывший ссылку с телефона, доскроллил до «Последних забегов».

# Часть II. Смелые идеи: нативные ощущения и истории

Всё выше — про то, чтобы сайт красиво прокручивался. Эта часть — про то, чтобы на него **хотелось
возвращаться** и чтобы им **хвастались в чате**. Аудитория делится примерно пополам между iPhone и
Android, и это не проблема, а ресурс: на каждой платформе можно взять то, что она умеет лучше, и не
пытаться причесать всё под общий знаменатель. Разное поведение на iOS и Android — нормально, если
ни одна из версий не выглядит обделённой.

## 11. Что реально умеет мобильный веб — карта возможностей

| Возможность                                     | iOS Safari / WKWebView                                      | Android Chrome / WebView            | Что делаем                                                           |
| ----------------------------------------------- | ----------------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------- |
| Вибрация `navigator.vibrate()`                  | **Нет**                                                     | **Да**, включая паттерны            | Android — полноценный тактильный отклик; iOS — обходной путь (§12.1) |
| Хаптик через `<input type="checkbox" switch>`   | **Да**, iOS 17.4+                                           | Нет (не нужен)                      | Единственный способ дать «щелчок» на iPhone                          |
| Scroll-driven animations (`animation-timeline`) | Safari 26+                                                  | Chrome 115+                         | Основной инструмент, с fallback                                      |
| View Transitions (same-document)                | Safari 18+                                                  | Chrome 111+                         | Переходы между страницами                                            |
| `navigator.share({ files })` — шеринг картинки  | **Да**                                                      | **Да**                              | Ключ ко всей механике «поделись карточкой»                           |
| DeviceOrientation (гироскоп)                    | Да, **только после `requestPermission()` по тапу**          | Да, без запроса                     | Гиро-эффекты: на Android сразу, на iOS — по явной кнопке             |
| Web Push                                        | Только для PWA, установленной на домашний экран (iOS 16.4+) | Да                                  | Уведомление «протокол опубликован»                                   |
| Установка на домашний экран                     | Вручную через «Поделиться» → нельзя вызвать программно      | `beforeinstallprompt` — своя кнопка | Разные сценарии онбординга                                           |
| Screen Wake Lock                                | Safari 16.4+                                                | Да                                  | Критично для `/timer`                                                |
| Badging API (значок на иконке)                  | Установленная PWA, iOS 16.4+                                | Установленная PWA                   | «Новый протокол» точкой на иконке                                    |
| Speech Synthesis                                | Да                                                          | Да                                  | Голосовой отсчёт на старте (опция)                                   |

Важная деталь: **ссылку откроют не в Safari и не в Chrome, а во встроенном браузере Telegram или
MAX.** На iOS это WKWebView (движок Safari, но без установки на домашний экран и без пуша), на
Android — WebView на базе Chrome. Значит:

1. Первое впечатление должно работать **внутри in-app браузера**, без установки, без разрешений.
2. Всё «нативное» (пуш, значок, установка) — второй шаг, к которому мы аккуратно ведём после того,
   как человек уже впечатлился.
3. Нужна ненавязчивая кнопка «Открыть в браузере» на тех сценариях, где in-app мешает.

## 12. Тактильность — то, чего нет ни у одного сайта в округе

Это самый недооценённый рычаг. Сайт, который **отзывается в пальцах**, мгновенно ощущается как
приложение.

**12.1 Единый сервис хаптики.**
Один `HapticService` с семантическими методами: `tick()`, `select()`, `success()`, `record()`,
`error()`. Внутри — две реализации:

- **Android:** `navigator.vibrate()` с паттернами. `tick` = 8 мс, `select` = 15 мс,
  `success` = `[12, 40, 24]`, `record` = `[10, 30, 10, 30, 60]` — нарастающая «фанфара».
- **iOS:** скрытый `<input type="checkbox" switch>` за экраном + `<label for>`; тап по label
  переключает свитч, и система выдаёт стандартный хаптик. Приём неофициальный, работает с iOS 17.4;
  оборачиваем в try/catch и в feature-detect, чтобы при поломке ничего не заметили.

**12.2 Где это применить (по убыванию ценности):**

- **`/timer`** — отсечка круга должна отдаваться в палец. Человек засекает, не глядя на экран;
  вибрация = подтверждение, что нажатие поймано. Это не украшение, это функция.
- **Обратный отсчёт** на главной в последние 10 секунд перед 8:00 в день забега — тик каждую
  секунду, на нуле — «фанфара».
- **Личный рекорд**: открыл свою строку в протоколе с «ЛР» → `record()` + конфетти.
- **Перетаскивание/свайпы** в админке и на таймере — `tick()` на каждом шаге.

**12.3 Обязательно:** переключатель «Вибрация» в настройках (device-local, рядом с «Выбери себя»),
и полное отключение при `prefers-reduced-motion: reduce`. Вибрация без спроса раздражает быстрее,
чем любая анимация.

## 13. Гироскоп и физика — «живая» глубина

**13.1 Гиро-параллакс героя.** Слои первого экрана (свечение, заголовок, карточка таймера) чуть
сдвигаются при наклоне телефона. Максимальное смещение 6–8 px — на большем начинает укачивать.
На Android включается сразу; на iOS — по тапу на подсказку «Наклони телефон» (требование
`requestPermission`), и эта подсказка сама по себе интригует: люди её жмут.

**13.2 Медаль/бейдж с бликом.** Бейджи года («30 финишей», «Король трассы») — это металл. Блик по
поверхности следует за наклоном телефона: `background-position` градиента привязан к
`DeviceOrientation`. На десктопе — за курсором. Это тот эффект, который люди показывают друг другу.

**13.3 Инерция в карточках.** Свайп по горизонтальной карусели (например, «Соперники» или бейджи)
с настоящей инерцией и лёгким «оверскроллом-резинкой» — CSS `overscroll-behavior` + `scroll-snap` +
хаптик `tick()` на каждом снапе. Ощущение фотогалереи в iOS.

## 14. Шеринг: wow начинается **до** сайта

Ключевое наблюдение: **первое, что человек видит — не сайт, а превью ссылки в чате.** Сейчас у нас
статические OG-теги (`docs/SEO.md`: один `og:image` 1200×630 на весь сайт). То есть ссылка на
протокол и ссылка на профиль выглядят в Telegram одинаково и безлико. Это самая дешёвая и самая
недооценённая точка роста.

**14.1 Персональные OG-картинки.**
При публикации забега (`publishEvent` и так коммитит в репозиторий) генерировать статические
превью:

- **на забег** — «Воскресный пробег, 26 июля · 47 финишёров · победитель 17:42 · погода −3 °C»;
- **на атлета** — имя, число финишей, лучшее время, полоска формы;
- **на дуэль `/vs`** — два имени и счёт встреч. Такое превью само провоцирует переслать.

Технически: HTML-шаблон → PNG на этапе публикации (в CI, где уже крутится Node), плюс маленькие
статические `index.html`-заглушки с нужными OG-тегами по маршрутам. Ботам Telegram/VK JS не
исполняют — теги обязаны лежать в HTML.

**14.2 «Карточка забега» — картинка, которой делятся.**
Кнопка «Поделиться» на странице атлета и в протоколе: генерируем в canvas вертикальную карточку
9:16 (формат сторис) — имя, время, место, темп, бейджи, фон в фирменной оранжевой палитре — и
отдаём через `navigator.share({ files })`. Работает и на iOS, и на Android; человек одним тапом
кидает её в чат или в сторис.

Это превращает каждого участника в канал распространения. Один забег = 40 карточек в чатах.

**14.3 «Итоги года» в формате сторис.**
Тот же генератор, но серия из 5–7 карточек: сколько пробежал, лучшее время, самый холодный забег,
серия недель, бейджи, место в рейтинге. Раз в год — гарантированный всплеск. Механика Spotify
Wrapped работает именно потому, что делиться приятно, а не потому, что данные интересные.

## 15. «Много разных историй» — сценарии, которые запоминаются

Ниже — самостоятельные истории. Каждую можно делать отдельно; вместе они дают ощущение, что сайт
живёт своей жизнью.

**15.1 Реплей забега.**
Главная фича-мечта. У нас есть финишные времена и сплиты первого круга (~70% покрытия). Этого
достаточно, чтобы **проиграть забег заново**: точки-бегуны едут по контуру трассы (тот же
`offset-path`, что и в §5.6), время идёт в ускоренном темпе, имена подписаны, своя точка
подсвечена. Ползунок, пауза, «показать только меня и соперников».

Человек, пробежавший 5 км в воскресенье, придёт смотреть, как он обгонял. Придёт не один раз. Для
неполных сплитов — честная оговорка «траектория восстановлена по времени финиша».

**15.2 Режим дня забега.**
В воскресенье с 7:30 сайт переключается в особый вид: на главной вместо обычного героя — «Сегодня
забег», живой таймер до старта секундами, погода на 8:00 у трассы (данные уже есть), карта сбора.
После финиша — «протокол готовится», а когда опубликован — сайт сам обновляет плашку. Возвращаться
в этот день становится осмысленно.

**15.3 Личная «дельта» — сравнение с собой прошлым.**
На странице атлета: два призрака на трассе — «ты сегодня» и «твой лучший забег». Видно, где выиграл,
где потерял. Плюс одна фраза: «на 14 секунд быстрее, чем в марте».

**15.4 «Пульс парка».**
Живая тепловая карта: сколько людей бежало в каждое воскресенье за всю историю, погода, температура.
Скроллится как лента лет. Красиво и уникально — таких данных больше ни у кого нет.

**15.5 Финишная лента и конфетти на рекорде.**
Когда человек открывает свой протокол с личным рекордом — короткая (1.2 с) анимация финишной ленты
поверх экрана + хаптик `record()`. Один раз на забег, с запоминанием в localStorage, чтобы не
повторялось при каждом заходе. Это момент, ради которого открывают протокол.

**15.6 Уведомление «протокол опубликован».**
Для тех, кто установил сайт на домашний экран: Web Push в момент публикации + значок на иконке
(Badging API). На Android — из коробки, на iOS — только для установленной PWA, поэтому на iOS
после первого финиша показываем аккуратную подсказку «Добавь на экран „Домой“, чтобы узнавать о
протоколе первым» с картинкой-инструкцией.

**15.7 Виджет обратного отсчёта.**
Нативных виджетов у веба нет, но: для iOS можно выложить готовый **ярлык Shortcuts / виджет
Scriptable** с таймером до ближайшего воскресенья, для Android — инструкцию по виджету-ярлыку.
Мелочь, которая живёт на домашнем экране и напоминает о себе каждый день.

**15.8 Голос старта.**
На `/timer` — синтезированный отсчёт «три… два… один… марш» через Speech Synthesis, плюс Wake Lock,
чтобы экран не гас во время замера. Строго опционально, выключено по умолчанию.

**15.9 Пасхалки.**

- Встряхнуть телефон на странице атлета → перемешать соперников / показать случайный забег из
  истории.
- Долгое нажатие на логотип → «сколько километров пробежал весь клуб суммарно» с бегущим счётчиком.
- 8:00 воскресенья: заголовок на секунду меняется на «Погнали».

Пасхалки почти ничего не стоят, а рассказывают о них месяцами.

## 16. Как это ранжировать

**Быстро и очень заметно:**

1. Хаптика на `/timer` и на счётчике (§12) — Android сразу, iOS через switch-трюк.
2. Персональные OG-картинки (§14.1) — работает даже для тех, кто на сайт не зашёл.
3. Кнопка «Поделиться карточкой» (§14.2).
4. Конфетти + лента на личном рекорде (§15.5).

**Средний кусок, высокая отдача:** 5. Режим дня забега (§15.2). 6. Гиро-блик на бейджах (§13.2). 7. Push + Badging + онбординг установки (§15.6).

**Большие истории (отдельный проект каждая):** 8. Реплей забега (§15.1) — главный кандидат на «фичу, ради которой возвращаются». 9. «Итоги года» как сторис (§14.3). 10. Пульс парка (§15.4).

## 17. Чего не делать

- **Звук без спроса.** Ни при каких условиях автозапуск.
- **Вибрация на каждый тап.** Хаптик — про подтверждение действия, а не про «мы умеем вибрировать».
- **Модалка «установите приложение» на первом заходе.** Убивает первое впечатление ровно у той
  половины, которую мы пытаемся впечатлить.
- **Запрос разрешения на гироскоп/уведомления до того, как человек что-то получил.** Только после
  ценности и только по явному тапу.
- **Тяжёлые библиотеки ради эффектов.** Бюджет 1.5/1.8 МБ, главная не ленивая. Конфетти пишется в
  60 строк на canvas, генератор карточек — на OffscreenCanvas, реплей — на SVG.
- **Ломать `/timer`.** Это рабочий инструмент волонтёра на морозе. Туда — только хаптик, Wake Lock и
  голосовой отсчёт, ничего декоративного.
